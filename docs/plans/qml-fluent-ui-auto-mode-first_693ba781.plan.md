## Цели

- **Визуал**: привести QML-интерфейс к современному виду в стиле Fluent WinUI 3 (тёмная тема, полу‑прозрачный/акриловый фон, плавные отступы и типографика).
- **Функциональность**: сделать AutoModePage полностью пригодной для реальной работы (путь выбора, запуск/отмена, прогресс, логи, диалоги шаблонов, диалоги недостающих файлов/ТБ).
- **Каркас**: закрепить навигационный каркас `Main.qml` и паттерны интеграции с `AppController`/`MissingFilesController`, чтобы по этому образцу потом перенести ручные режимы.

- **QML корневое окно**: `[ui/qml/Main.qml](c:\Users\icehole\git\DubbingTool\ui\qml\Main.qml)`
  - `ApplicationWindow` с тёмным фоном (`#202020`), левым сайдбаром и `StackLayout` страниц.
  - Сайдбар сейчас простой `Rectangle + ListView + ItemDelegate` с иконками-эмодзи и жёстко заданными путями страниц.
  - В контенте реальная страница только одна: `AutoModePage`; остальные — `PlaceholderPage`.
- **AutoModePage**: `[ui/qml/pages/AutoModePage.qml](c:\Users\icehole\git\DubbingTool\ui\qml\pages\AutoModePage.qml)`
  - Уже реализует **почти полный рабочий поток** автоматического режима: поля ввода (шаблон, MKV, аудио, свои субтитры/надписи, номер серии, флаг нормализации, decouple), логи в `TextArea`, прогресс/этапы, кнопка `СТАРТ/ОТМЕНА`.
  - Жёстко завязана на `AppController` (QML-синглтон) для загрузки шаблонов, старта/отмены, логов (`Connections` на `logMessage`, `pauseForSubEditRequested`, `signStylesRequested`).
  - Внешний вид уже тёмный, но пока без акрилового/мика фона, Fluent-контролы используются базово.
- **Диалоги и доп. страницы QML**:
  - `PlaceholderPage.qml` — заглушка «Страница в разработке».
  - `TemplateEditorDialog.qml` — большой диалог редактирования шаблона (много вкладок, GridLayout'ов, TextArea и т.п.), тесно интегрирован с `AppController` (загрузка/сохранение JSON шаблона и пресетов).
  - `MissingFilesDialog.qml` — продвинутый диалог недостающих файлов/шрифтов/времени ТБ, использует `AppController.missingFiles` и `VideoOutput` для просмотра видео и скраббинга по таймлайну.
- **C++ glue для QML**:
  - `[src/core/appcontroller.h/.cpp](c:\Users\icehole\git\DubbingTool\src\core\appcontroller.h)` — `QML_SINGLETON` с Q_PROPERTY и Q_INVOKABLE методами для шаблонов, старта воркфлоу, отмены, разбора ASS для стилей/актёров, прокидывания запросов пользователя в `MissingFilesController` и обратно в `WorkflowManager`.
  - QML уже опирается на эти API; с точки зрения логики бэкенда AutoModePage можно считать «почти готовой», упор — в дизайне и UX.

## План по шагам

### 1. Уточнить и зафиксировать визуальные принципы Fluent/акрила (без кода)

- **Тёмная Fluent база**:
  - Использовать стиль `FluentWinUI3` (как уже делается в `main.cpp`) как базовый.
  - Для цветов не хардкодить сплошные `#202020`, а опираться на палитру `window.palette`/системные цвета и единообразные оттенки для фона/границ.
- **Атмосфера «акрила»/мики без завязки на Win‑API**:
  - На QML-уровне спланировать сочетание: тёмный градиентный/полупрозрачный фон + блюр/акрил через слои (`Rectangle` с `opacity < 1`, фоновые декоративные элементы).
  - Определить базовый layout: боковой нав-бар с мягкими углами, отступы 16–24px, карточный вид для контента (контейнер для AutoModePage, диалогов).
- **UX‑принципы для AutoModePage**:
  - Формы: выровненные подписи и поля, читаемые плейсхолдеры, группировка по смыслу (источники, субтитры, надписи, доп. опции).
  - Логи: визуально выделенная консоль с явным заголовком, фиксированной моноширинной гарнитурой и удобным копированием.
  - Кнопки: доминантная primary-кнопка «СТАРТ/ОТМЕНА», вторичные — одинаковой высоты и отступов.

### 2. Доработка каркаса `Main.qml` (на уровне дизайна и структуры)

- **Сайдбар**:
  - Запланировать переход с кастомного `Rectangle + ListView` на `NavigationView`‑подобный паттерн из Qt Quick Controls (оставаясь в рамках доступных контролов) или хотя бы привести `ItemDelegate` к виду Fluent: подсветка текущего, hover‑эффект, иконки из иконшрифта вместо эмодзи.
  - Определить набор пунктов, который в будущем отразит реальные режимы: Авто, Ручная разборка, Ручная сборка, Рендер, Публикация, Настройки.
- **Контентная область**:
  - Описать контейнер «карточки» для страниц: фон с лёгкой прозрачностью и скруглёнными краями внутри отступов окна.
  - Зафиксировать, что **AutoModePage** — эталон по структуре: сверху форма, посередине логи, снизу прогресс и управление.
- **Интеграция с AppController**:
  - Сохранить текущую схему: `DubbingTool` QML‑модуль, `AppController` как QML‑синглтон.
  - В будущем предусмотреть место для глобальных уведомлений/ошибок (например, `Snackbar`/`Dialog`) поверх `ApplicationWindow`.

### 3. Дизайн‑ и UX‑шлифовка AutoModePage (без переписывания логики)

- **Формы**:
  - Переразместить сетку `GridLayout` так, чтобы подписи были компактнее, а поля занимали основную ширину.
  - Унифицировать высоту `TextField`/`Button`, убрать визуальный шум (лишние рамки, грубые цвета).
- **Логи**:
  - Оставить `ScrollView + TextArea`, но обновить фон и границы под общий акриловый стиль, добавить явный заголовок «Журнал» и индикатор «живого» лога.
- **Кнопка старта/отмены и прогресс**:
  - Спроектировать более читаемую строку состояния («Текущий этап: …») и прогресс‑бар, возможно с подсказкой о длительных шагах.
  - Держать кнопку `СТАРТ/ОТМЕНА` максимально заметной, с явным состоянием «занят / свободен».

### 4. Объединение QML‑диалогов в единую визуальную систему

- **TemplateEditorDialog.qml**:
  - Оставить структуру вкладок, но привести фоны, границы и отступы к тем же правилам, что и для AutoModePage.
  - Продумать, какие поля наиболее критичны, и как визуально не перегрузить пользователя (возможно, разделить группы заголовками/подсветкой).
- **MissingFilesDialog.qml**:
  - Убедиться, что внешний вид (тёмный фон, границы, скругления) совпадает с общим акриловым стилем.
  - Видеоплеер/слайдер времени и список шрифтов — спроектировать как отдельные визуальные блоки внутри диалога.
- **Глобальные принципы**:
  - Определить общие отступы, радиусы скругления, цвета рамок, чтобы диалоги не выглядели «из разных миров».

### 5. Переходный режим: сосуществование QML и виджетов

- Оставить `MainWindow` (виджетный UI) как **legacy**, пока QML‑интерфейс не восстановит полный функционал.
- В `main.cpp` держать одновременный запуск QML окна и виджетов до этапа, когда можно будет безопасно выключить `MainWindow`.
- При дальнейшем планировании (после AutoModePage) использовать текущую структуру `MainWindow` (`extractTab`, `assemblyTabLayout`, `renderTabLayout`, `PublicationWidget`) как источник требований для будущих QML‑страниц.

### 6. План на будущие итерации (после доводки AutoModePage)

- **Ручная разборка/сборка/рендер**:
  - По мотивам legacy‑виджетов и AutoModePage описать QML‑страницы для ручных режимов с тем же визуальным каркасом.
- **Публикация и шаблоны постов**:
  - Перенести логику из `PublicationWidget` и работы с `ReleaseTemplate` в отдельную QML‑страницу, используя уже существующий TemplateEditorDialog.
- **Отказ от виджетного MainWindow**:
  - После достижения функционального паритета по основным режимам, убрать создание `MainWindow` в `main.cpp`, оставив только QML окно и (опционально) вернуть Windows‑специфичный код DWM/Mica поверх QML‑окна.

## Итог

После реализации этого плана AutoModePage и связанные QML‑диалоги станут полноценным, визуально современным интерфейсом в стиле Fluent WinUI 3 (тёмная тема, акриловый вайб), а `Main.qml` — устойчивым каркасом для дальнейшего переноса остальных режимов. Все изменения будут максимально опираться на уже существующую C++‑логику (`AppController`, `MissingFilesController`, `WorkflowManager`), без её перелома.
